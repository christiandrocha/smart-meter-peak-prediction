## What Shipped

AC66_BOTH_LEGS F-03 is closed (follow-up file `.claude/sdd/follow-ups/F_AC66_BOTH_LEGS_03.md`).
Both AC-66 live legs now read the run ids of `smart_meter_peak_model` before anything else and
again after the refusal or the job run, and compare them by run id. A leg in the wrong table state
still refuses before any job run and changes no evidence file. What is new is the workspace
check, which the test itself makes and which no longer depends on an operator reading the CLI:

- A clean refusal ends with `0 new runs of smart_meter_peak_model (newest run before: <id>, after: <id>)`.
- A refusal during which a run appeared fails with its own first line that lists the new run ids
  (AC-167).
- A pass needs exactly one new run, and it must be the leg's own run id; a pass prints one line
  with its run id (AC-168).
- A run list that cannot be read never reports a pass or a clean refusal (AC-169).

The pure rule is `count_runs` in `tests/support/ac66_rules.py` (no SDK, no I/O, no clock). The live
reader is `PeakRunner.run_ids` in `tests/integration/conftest.py`: one Jobs API list request for the
peak job id, every life-cycle state, one page of 25. `run_leg` takes a required `runs` keyword, so a
caller that forgets it fails with a `TypeError`. The runbook (`docs/runbooks/peak_model.md`,
sections 8 and 9) and the leg command lines carry `-rP`, so the pass line is printed.

Nothing under `src/`, `resources/`, `notebooks/`, `databricks.yml` or `scripts/reset_peak_model_outputs.py`
changed (AC-171, against tag `v0.7.0`).

## Self-Review

- **Weak points:** The live criteria rest on one run of the sequence on `dev`, on one day. A-54 was
  checked once (4.3 s). The leg tests pin the exact call order of `run_leg`, so a harmless refactor
  needs those tests to change. AC-171 detects removed assertions, not weakened ones (F-03).
  The pass line appears only with `-rP` (AC-172 guards the command text, not an operator's habit).
- **Risks:** A run started by someone else between the two reads is counted as new and fails the
  leg (Q-36 accepted this). A foreign run during the rebuild
  leg's pass path costs a new sequence with a reset. The chain choice of DA-52 (I-08) is open, so
  reader text can show in pytest output. The tag `v0.7.1` and the package version 0.4.1 differ, as
  in v0.5.0 to v0.7.0 (D-99). The AC-119 archive simulation skips again after this archive (AC66_BOTH_LEGS F-06).
- **What I would do differently:** Write the exit paths of a side-effecting procedure, with the
  chain choice for each message, into the DESIGN test table before the build, so that the review
  finds fewer gaps. Give `PeakRunner` a ledger of the run ids it started itself, as the DESIGN's
  Self-Review proposed, so that a run started by the test process is told apart from a foreign run.
- **Next improvement:** Cut tag `v0.7.1` on the ship PR's merge commit (F-04). Then `/iterate` on
  DA-52 if the operator wants `from None` (F-02), and AC66_BOTH_LEGS F-06 so that the archive rules
  run again in the default test run.
