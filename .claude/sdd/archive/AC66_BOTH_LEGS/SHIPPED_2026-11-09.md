## Lessons Learned

Drafted by the ship agent from the BUILD_REPORT, the DESIGN and the ship session of 2026-11-09.
Not yet confirmed by the user.

| Category | Lesson | Action for future features |
|---|---|---|
| Process (git and pull requests, drafted from the ship session) | The spec PR was reported as merged three times before `gh pr view` showed it. At that moment #53 was `OPEN` and its `checks` job was still running. The verify-before-acting rule of `docs/conventions/git.md` held: no post-merge step ran on the stated state, and the record uses the `gh` reads only | Read the state with `gh pr view` before each post-merge step, and record a merge only from that read. Wait for `checks` to finish before a merge is asked for |
| Platform (CI, drafted from the ship session) | The CI `checks` job takes about 6 minutes and blocks the merge. A spec, build and ship chain therefore waits about 6 minutes at each merge | Plan the merge order of a chain with that wait; do not chain a merge after a `checks` run that has not finished |
| Process (live constraint, drafted from the BUILD_REPORT) | C-23 says agents never run the reset with `--confirm`. The user authorized the agent to run the live sequence and the reset for this one run, with the condition that `--confirm` ran only if the dry run listed exactly the three `dev` tables. The condition held. The override is recorded in the BUILD_REPORT Summary and Live run record, but not in its Deviations table | Record a per-run authorization of a DEFINE or DESIGN constraint in the Deviations table, with the user's words and the date. Keep the dry-run condition written as a gate, as U-06 did |
| Design (text copied into code) | Two text blocks of the DESIGN were over the 100-character ruff limit: a 111-character reset usage line and the first line of the `test_peak_data.py` docstring. The build made both mechanical changes (BUILD_REPORT Deviations, rows 2 and 3) | Check the code and text blocks of a DESIGN against the project's line length before the DESIGN is `Ready for Build` |
| Design (module loading) | DA-44 said to load `tests/integration/conftest.py` by path under a private name. That failed with `AttributeError`, because `dataclasses` resolves string annotations through `sys.modules`. The build registered the module in `sys.modules` (BUILD_REPORT Deviations, row 1) | When the DESIGN loads a module by path and the target uses dataclasses, prototype the load on the real module before the build and name the `sys.modules` step |
| Build review (side-effect order) | The code review found three Medium gaps after the DESIGN test table: the after-state mismatch was not checked through `run_leg`, the preflight-before-removal order was untested, and the unreadable-snapshot case was missing. All were fixed in f113d88 (BUILD_REPORT I-03) | For a procedure with side effects, list the order of the side effects and every after-state check as rows of the DEFINE test table, so the review finds fewer gaps |
| Spec (live assertions) | "0 new runs" in AC-162 and AC-164 is read by the operator from the CLI, not asserted by the test. The DESIGN and the BUILD_REPORT both name it as the thing they would change | A live test that claims that a step started nothing asserts it itself (F-03) |

## Self-Review

- **Weak points:** The live criteria rest on one run of the sequence on `dev`, on one day. The
  "0 new runs" of AC-162 and AC-164 is an operator reading (F-03). The verdict reads local files
  and trusts them (accepted in the DEFINE). The AC-159 AST rules check the shape of today's live
  tests (F-05).
- **Risks:** `dev` now has the three tables rebuilt by the rebuild leg, and the snapshot and leg
  files of this run are local to one checkout (C-25). A failing rebuild leg leaves a partial state
  that both legs refuse until a full run of `smart_meter_peak_model`. The clock order (A-49) rests
  on one machine's wall clock. The AC-119 archive simulation skips in the default run because nothing is left to simulate (F-06), so the archive rules are not exercised by CI until the next feature. The tag `v0.7.0` and the package version 0.4.1 differ, which a reader
  of `pyproject.toml` may find surprising (D-92; Template Feedback). The per-run override of C-23
  rests on the user's message of the session, recorded in the BUILD_REPORT and not in a DEFINE or
  DESIGN revision.
- **What I would do differently:** Write the order of the side effects and the after-state checks
  into the DEFINE test table, so that the review does not find the three Medium gaps. Record a
  per-run authorization of a constraint in the Deviations table on the day it is given. Have the
  leg tests assert "0 new runs" themselves.
- **Next improvement:** Tag `v0.7.0` after the ship PR merges (F-04), then F-03, the leg tests that
  assert "0 new runs" themselves.
