## What Shipped

The live test `test_ac97_check_refuses_while_an_update_is_active_and_the_rerun_succeeds` now records
the timing of its own run. It writes `out/evidence/ac97_timing.json` (git-ignored) in an outer
`finally`, also when an assertion fails. The file holds the no-op update's creation and end, the
refused run and its check task, what the check read, and the rerun. The margin
`read_after_creation_seconds` and `update_outlived_read_seconds` are in it. Pure, SDK-free helpers
in `tests/support/ac97_timing.py` build the record. The new live test
`test_ac106_ac97_timing_evidence_matches_the_platform` reads the file and cross-checks it with three
platform reads. It starts nothing. The runbook has a subsection "AC-97 timing evidence" in
`docs/runbooks/meter_ingestion.md`, and row H points to it. The layout rule in
`tests/test_integration_layout.py` accepts two or three digit AC names. No production code, job,
pipeline, bundle or notebook changed. The package version is 0.4.1.

This feature closes INGESTION_GUARD follow-up F-05 (the margin was only visible in the Jobs API).

## Lessons Learned

These are the ship agent's reading of the build report, drafted from the build report and the
spike. The user was not asked during this ship. Every row is marked *drafted, not confirmed by the
user*.

| Category | Lesson | Action for future features |
|---|---|---|
| Platform timing (drafted, not confirmed by the user) | The no-op update lasted 59 s on 2026-11-04, while spike 06 measured 125 s. The AC-97 margin was 32 s, not the roughly 100 s the spike figure implied (I-13). Measured platform timings drift between days, so a test that depends on one cannot rely on the spike number | A live test that depends on a platform timing records that timing in the evidence file on every run, and the DESIGN lists the margin as a risk with its observed range, not a single value |
| Tooling (drafted, not confirmed by the user) | The pre-commit ruff (v0.6.9) and the dev ruff (0.17) formatted one long `assert` in `tests/test_integration_layout.py` differently again. The fix was to move the message to a variable, so both agree. This is the same cause as PEAK_MODEL F-02, still open | Close PEAK_MODEL F-02 (pin the pre-commit ruff to the dev version) before the next feature that adds an `assert` with a long message |
| Spec, numbering (drafted, not confirmed by the user) | The first three-digit AC (AC-100, and AC-106 for the live test) broke the two-digit name rule `^test_ac(\d{2})_` in the layout test (C-15). The DEFINE found it by code reading; the DESIGN chose the fix (OD-24). The rule was correct for the series until then | When an ID series crosses a digit boundary (99 to 100, 999 to 1000), check every regex, fixed-width format and sort order that reads the IDs. Put this in the DEFINE constraints as a row, not as a surprise in the build |
| Process, subagents (drafted, not confirmed by the user) | A subagent without Bash could not run `scripts/check_specs.py` or the test commands during its run, so the gates had to be run by the caller | Give the build and ship subagents the Bash tool, or have the calling session run the gates and record the output in the report |
| Live evidence (drafted, not confirmed by the user) | INGESTION_GUARD F-05: the margin of AC-97 existed only in the Jobs API after the run, and the run could be pruned. This feature writes the margin during the run, and the first live run confirmed the fields are filled (no `null` in the timing fields) | Keep the rule from INGESTION_GUARD: a timing margin that matters is saved by the test during the run |

## Self-Review

- **Weak points:** The live evidence is one run on `dev` (AC-97 and AC-106 on the same day). The margin of 32 s rests on one update; the live capture helpers have no unit test (F-01). The evidence file is overwritten by each run, so only the copy in the BUILD_REPORT keeps the first numbers.
- **Risks:** The platform update time drifted by half from the spike figure (59 s against 125 s). If it drifts further, AC-97 can pass vacuously, and AC-106 would then show `update_ended_before_check` in the file rather than fail the release. The check_specs gap means the archived documents are not checked by CI (F-07).
- **Trade-offs:** The margin is recorded, not compared with a threshold. That keeps AC-97 as it was (no new failure mode) but leaves the decision to a person reading the file.
- **Next step:** Open the ship pull request on `ship/ac97-timing-evidence` (stacked on build PR #33, which stacks on spec PR #32; retarget to `main` in merge order), merge in order, tag `v0.4.1` (F-06), and run AC-97 and AC-106 again after the next deploy to add a second observation of the margin (F-02).
