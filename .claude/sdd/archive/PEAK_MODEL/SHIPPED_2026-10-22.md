## What Shipped

A daily path on top of the METER_INGESTION Gold tables that predicts, for each eligible household,
whether the next day's consumption will be a spike. Weather is ingested from a Volume into Bronze and
Silver. Features and labels are built as dense, point-in-time ML tables. An on-demand training job
fits one deterministic gradient boosting model per run, logs it to MLflow, registers it in Unity
Catalog and promotes it with the `champion` alias. The decision threshold is stored as a version tag.
The daily job scores the target date with the champion. The feature's decisions are recorded in
ADRs 0007 to 0011, and its data contracts are in `docs/contracts/`.

## Lessons Learned

What slowed the feature down (confirmed at ship): the PR 2 gate failures. Three training runs failed
on platform behaviour that the spikes and the fakes had not probed (D-20 to D-23), and each one cost
a fix, a redeploy and a rerun. What the spec missed (confirmed at ship): the DA-13 retry, the second
leg of AC-66, and the only reload path for an FE model on serverless (G-08). Actions are F-14 to F-16
and the ADR 0007 note of 2026-10-22.

| Category | Lesson | Action for future features |
|---|---|---|
| Platform (serverless auto-optimization) | Serverless auto-optimization retried failed tasks even with `max_retries: 0`. The job settings show `max_retries` unset, so the retry does not appear in the configuration (D-21) | Set `disable_auto_optimization: true` on every task where a second attempt is unsafe (training is one). Count attempts in tests that depend on them. METER_INGESTION `ingest_kafka` has the same pattern (METER F-05) |
| Platform (serverless environments) | The default serverless environment is Python 3.12, where `scikit-learn==1.3.0` builds from source and fails (D-19) | Pin `environment_version` on every notebook task (version 2 here) and test the pin (G-01) |
| Platform (Feature Engineering signature) | `fe.log_model` adds the lookup keys (`household_id`, `target_date`) to the model signature. A features-only frame fails schema enforcement (D-22) | Build the reload input from the registered signature, including the lookup keys, or score by version (next row) |
| Platform (Feature Engineering on serverless) | `mlflow.pyfunc.load_model` of an FE model calls `score_batch` with a local URI, which serverless rejects. `fe.score_batch` by model version reproduces the logged scores exactly (D-23) | Verify an FE model by `fe.score_batch(model_uri="models:/<name>/<version>")`, never by `pyfunc.load_model`. Implemented in `registry.fe_reload_scores` |
| Platform (Unity Catalog search) | Model-version search accepts a name-only filter. `name = ... and run_id = ...` fails with `INVALID_PARAMETER_VALUE` after the version was registered (D-20) | Filter by name and match `run_id` in code. Fakes must reject filters that Unity Catalog rejects (the registry fake does) |
| Platform (Jobs and Pipelines API) | `jobs.list` omits job parameters. The pipeline API omits `continuous` when it is false | Read job settings with `jobs.get`. Compare pipeline flags as `bool(...)` |
| Platform (pipeline concurrency) | An update requested while another update of the same pipeline runs is refused in about 2 s. The task ends `INTERNAL_ERROR`, and the job does not retry it despite `max_retries: 1` (DA-13) | Schedule the peak job so that it does not overlap ingestion, accept the failed run, and let the next daily run retry (runbook, Concurrency). The integration runner refuses combined runs |
| Build (fakes against the platform) | The platform-facing code (registry, MERGE writer, FE client) was tested only with fakes until the gate. Three training runs failed on behaviour the fakes did not model (D-20, D-22, D-23), and the first failure also retried (D-21). Each failed run left a registered model version that needed cleanup | Probe every client call the DESIGN depends on in a scratch run before the build, and record the probe in the runtime ADR. Fakes check the call shape, not the platform rules |
| Build (Spark and pandas boundary) | `toPandas` turns a nullable integer label into a float, and a pandas timestamp reaches a Feature Engineering lookup as TIMESTAMP, not DATE (D-13, D-11) | Cast labels and lookup keys explicitly at every Spark and pandas boundary, and test the dtype |
| Build (empty or partial source) | A change-only MERGE with delete-by-source removes every row when its source is empty (D-17). A `replaceWhere` over a date without label rows silently deletes that date's earlier predictions (D-07) | Guard every Delta write against an empty or incomplete source before it runs (G-06, G-12) |
| Build (shared schema objects) | `StructType.add` mutates a shared library schema, so a second use fails with a duplicate column (D-14) | Copy a shared schema before adding columns |
| Build (local stack) | `pyarrow` 22 and later need NumPy 2, which scikit-learn 1.3 cannot import (D-01) | Pin the local ML stack to the platform versions in the dev extra |
| Tooling (pre-commit against CI) | The pre-commit ruff (v0.6.9) and the CI ruff (0.17) format long asserts differently. `pre-commit run --all-files` skips untracked files | Bump the pre-commit pin (F-02). Run the hooks on staged files before a gate |
| Spec (partial legs) | AC-66 names a rebuild after the outputs are dropped. The build report marked the AC `Pass` after the rerun leg alone; the ship review caught it and the rebuild leg ran before the release | An AC names every leg it needs. A leg that did not run makes the AC `Partial` |

## Decisions to Carry Forward

| ADR / decision | Why it matters for later features |
|---|---|
| 0007 PEAK_MODEL runtime and data assumptions | The spike 05 outcomes and the chosen variant: MLflow and Unity Catalog behaviour, the Feature Engineering client, serverless limits. Every later ML feature on this stack starts from these records |
| 0008 Jobs and pipeline dependency | The daily job runs the shared Silver and Gold pipeline first; training is a separate on-demand job without retries. Any new job that writes shared tables follows the same pattern and the same overlap rule (DA-13) |
| 0009 Decision threshold as model version tag | Scoring reads the threshold from the tag of the `champion` version; ties go to the highest threshold. A change to threshold rules needs a new ADR |
| 0010 Consumption spike label definition | The label is strictly above 1.3 times the median of the last four complete same-weekday days within eight weeks. The label parameters are table properties (AC-63). A change to the label rule is a change of training data: `/iterate` and a new ADR |
| 0011 Dense ML tables and run-artifact training sets | Feature and label tables are dense per household and date (AC-41). A training set is rebuilt from the logged table versions, not stored as a table (AC-55) |
| Platform rules applied in code | Score Feature Engineering models by version with `fe.score_batch`; pin `environment_version` on every notebook task; disable auto-optimization on the training task; filter model versions by name only |
| Runbook rule: retrain after every redeploy | The `git_commit` check of a model run goes stale after a redeploy (accepted, PR 3 review). Retrain after each deploy before the daily job uses the champion |

## Self-Review

- **Weak points:** The live evidence covers one seed-42 dataset and one Free Edition workspace. AC-61 and AC-53 have no live test. The platform code was verified by fakes until the gate, and the gate found three mismatches. Local scikit-learn is 1.3.2, the platform pin is 1.3.0, so determinism on the platform rests on live AC-49.
- **Risks:** The daily job and the ingestion job share one pipeline. Overlap is prevented by the schedule, not by a lock: a run started during ingestion fails with `INTERNAL_ERROR` and is retried only by the next daily run. Scoring depends on the `champion` alias; a missing alias fails before any write (AC-61, unit only). Serverless behaviour may change; the environment version is pinned, not the platform.
- **Trade-offs:** Change-only MERGE keeps ML tables dense and cheap to rerun, but every parameter update commits a Delta version (F-10). Training sets are run artifacts, not tables (ADR 0011): reproducibility rests on the logged table versions, and a rebuild costs compute. Fake-based unit tests run locally in seconds; the platform gate costs a run per fix. Three training attempts failed at the gate before the platform rules were known.
- **Next step:** Merge the ship PR and cut the tag `v0.2.0`. Then F-02 and F-05 in the next release.
