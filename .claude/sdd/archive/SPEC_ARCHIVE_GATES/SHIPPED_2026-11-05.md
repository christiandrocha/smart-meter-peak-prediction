## What Shipped

`scripts/check_specs.py` now checks the shipped specs in `.claude/sdd/archive/`, not only
`features/` and `reports/`. Archived phase documents get the existing rules, with traceability
inside each archive folder. Rule (a) requires every archived document to be in its phase's final
status and each folder to hold exactly one `SHIPPED_YYYY-MM-DD.md` with status `Shipped`. SHIPPED
documents are a checked phase: the file-name date must equal the `Shipped on` row, every template
section must be present with a non-empty Self-Review, and from the cut-off date 2026-11-05 also
`Pull Requests and Branches` and no unfilled placeholders. Rule (b) warns for each archived finding
whose Follow-up cell starts with `Open`. Rule (c) requires a finding ID from another spec to carry
that spec's folder name in front (a soft wrap is allowed, a blank line is not); the 17 existing
unprefixed citations are frozen with exact counts in `.claude/sdd/citation_allowlist.json`
(12 entries). The SHIPPED template gained `## Self-Review`, and the SDD README describes the checks.

Entry points: `scripts/check_specs.py` (`check_archive`), `.claude/sdd/citation_allowlist.json`,
`tests/test_check_specs.py` (AC-107 to AC-119), `.claude/sdd/README.md`.

This SHIPPED document is the first one written under the new rules, and the archive pass checks
this folder from the moment it lands.

## Lessons Learned

All drafted from the build evidence and the user's notes of 2026-11-05.

| Category | Lesson | Action for future features |
|---|---|---|
| Spec (discovery) | Discovery measured sections, dates and Self-Review of the SHIPPED documents but not the placeholder rule that SHIPPED inherited, so Gap A appeared only at the build (BUILD_REPORT I-03) | Before the DEFINE, run every rule a new scope inherits on the real data, not only the new rules |
| Build (evidence) | The Build Evidence of the BUILD_REPORT was generated on c18bb0a, an intermediate commit, and not on the final build head 29f35a9 (the counts held on `main` 605f133: 52 documents, 0 errors, 2 warnings) | Generate the Build Evidence on the final head of the build branch and record that SHA in the report |
| Spec (counts) | The discovery reported 14 frozen citations; the exact rule gave 17 in 12 entries (DEFINE Q-27) | Measure with the exact rule definition, including fenced code and defining rows, before reporting a count |
| Build (stop rule) | Stopping on the two gaps and resolving them through an `/iterate` commit before any code kept the design and the code in step | Keep "stop and report with file:line" for design gaps found during a build |
| Process (manual checks) | A manual self-check of the spec documents caught real violations twice (unprefixed examples; a wrapped prefix) before it became the AC-119 test | Turn a manual check that finds defects into a test in the same feature |

## Self-Review

- **Weak points:** Rule (c) is a heuristic over prose and sees only IDs that the citing spec does
  not define; the 433 ambiguous citations stay unchecked (F-02). Rule (b) depends on the word
  `Open` (BUILD_REPORT I-01). The Build Evidence was generated on an intermediate commit.
- **Risks:** The 9 allowlisted files cannot be edited without updating their entries. The
  placeholder rule will flag braced paths in new SHIPPED documents until F-04 is decided. The
  template repository still has the old script (F-01).
- **What I would do differently:** Measure every inherited rule before the DEFINE, and generate the
  Build Evidence on the final head.
- **Next improvement:** Port the change to the template repository (F-01).
